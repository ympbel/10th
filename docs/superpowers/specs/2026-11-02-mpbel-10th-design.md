## 1. 의도와 배경

연세 의학물리 및 의공학 연구실(MPBEL, 지도교수 김진성)은 2016년 연세대학교 의과대학 방사선종양학교실에서 시작해 2026년에 10년이 된다. 이 사이트는 그 10년 동안 연구실을 거쳐 간 사람과 그들이 남긴 논문·특허·발표·수상·과제·세미나를 한곳에 기록하는 **아카이브**다.

가장 전형적인 쓰임은 **교수님이나 구성원이 외부 사람에게 연구실을 소개하며 링크를 보내는 장면**이다(사용자 확인). 링크를 받는 사람은 연구실을 잘 모르는 외부인(예비 지원자, 협력 연구자, 평가자)이고, 몇 분 안에 "어떤 사람들이 있었고, 10년 동안 무엇을 얼마나 냈고, 해마다 꾸준했는가"를 파악할 수 있어야 한다. 졸업생의 회고나 추억 수집은 목적이 아니다(사용자: "졸업생은 별로 중요하진 않음").

MPBEL 메인 사이트(`https://ympbel.github.io/`)는 운영용이다. 이 사이트는 메인 사이트의 식구로 보이되(같은 디자인 시스템, 하위 경로), 메인 사이트에 없는 것을 담는다. 연도별 단면, 사람과 성과의 연결, 운영 시트에만 있던 자료(논문 IF, 과제의 부처·사업·기간·연구비, 수상, 학회 초록).

### 성공의 모습

1. 외부 방문자가 홈 첫 화면에서 연구실 이름과 기간, 규모(숫자 여섯 개)를 읽고, 한 번 스크롤하면 해마다 쌓인 성과와 사람을 읽는다.
2. 연도를 고르면 그 해의 연구실(합류한 사람, 학위를 받은 사람, 논문, 발표, 수상, 진행 중이던 과제)이 한 화면에 보인다.
3. 구성원·졸업생이 자기 이름을 누르면 자기가 남긴 논문·발표·수상이 모인 페이지가 나온다.
4. 운영자가 마크다운 파일 하나를 추가하고 커밋하면 몇 분 뒤 사이트에 반영된다.
5. 개인정보(연락처, 생년월일, MBTI, 학번, 등록번호, 과제 실무담당자)가 저장소에도 사이트에도 없다.
6. 메인 사이트가 `mpbel.yonsei.ac.kr`로 옮겨 가도 설정 한 줄만 바꾸면 된다.

## 2. 범위

### 2.1 목표 (1차)

- **홈**: 메인 사이트 홈의 뼈대(비주얼 띠 → 소개 띠) 위에 열한 해(2016–2026) 연표와 연도 패널, 게시판 바로가기를 얹는다. (5.3)
- **연도 페이지 11개**: `/years/2016/` … `/years/2026/`. (5.4)
- **게시판 11개**: 학생 현황, 졸업 현황, 논문, 특허, 발표, 수상, 과제, 세미나, 워크샵, comments, 사진. 이 중 워크샵·사진·comments는 자료가 없어 **빈 게시판 틀, 항목 형식(템플릿), 빈 상태 안내**까지만 만든다. (5.5)
- **개인 페이지**: 학생·졸업생·거쳐 간 구성원마다 한 쪽. 그 사람이 1저자·공동1저자·교신저자인 논문, 저자로 들어간 학회 발표, 수상을 모은다. (5.6)
- **한·영 UI**: `/en/` 아래 같은 구조. 메뉴·라벨·안내문은 두 언어로 쓴다. 데이터는 영문 값이 있는 것(영문 이름, 영문 제목)만 영어로 나오고, 한글만 있는 값(학과, 직장, 과제명, 부처명)은 영문 페이지에서도 한글 그대로 나온다. (5.8)
- **데이터 변환 1회**: `data/`의 구글 시트 HTML 내보내기 7장과 MPBEL 사이트의 특허 7건·세미나 431건 메타데이터를 마크다운 파일로 옮기는 스크립트. 한 번 돌리고, 이후는 파일을 직접 편집한다. (5.7)
- **GitHub Pages 자동 배포**: `ympbel/10th` 공개 저장소, `main` push → 테스트 → 빌드 → 배포. (5.10)
- **운영 안내 README**(한글): 종류별 "항목 추가하는 법", 별칭(aliases) 관리법, 사진·워크샵·comments 채우는 법, 도메인 전환 때 바꿀 것.

### 2.2 비목표 (1차에서 하지 않는 것)

- 구글 시트와의 동기화, 빌드 때 시트 읽기. (사용자 결정: 한 번만 변환)
- comments를 실제로 받는 장치(폼, 댓글 위젯). 방식 미정. 페이지와 파일 형식만 만든다.
- 사진·워크샵 내용. 사용자가 추후 제공한다.
- 한글 데이터의 영문 번역. `*_en` 필드는 비워 두고, 채우면 영문 페이지가 자동으로 쓴다.
- 검색, 로그인, 조회수, 댓글, 관리자 화면.
- 메인 사이트 변경. `../Website_20261028`과 `ympbel/ympbel.github.io`는 읽기 전용이다.
- 2020년 이전 세미나, 2017년 이전 학회 발표, 2018년 이전 수상, 초청 강연. 자료가 없다.
- 도메인 연결 작업. 메인 사이트가 전환되면 `site` 값만 바꾼다(5.10).

### 2.3 반목표 (이렇게 되면 기술적으로 돌아가도 실패)

- 개인정보가 저장소(git 이력 포함)나 빌드 결과에 들어감. `data/` 폴더가 커밋됨.
- 시트에 없는 숫자·이름·날짜·소개 문구가 만들어져 들어감. 빈 게시판을 가짜 내용으로 채움.
- 홈이 메인 사이트 홈과 똑같아 보여 "10년의 기록"이라는 신호가 첫 화면에 없음.
- `/`로 시작하는 경로가 `base` 없이 쓰여 링크·이미지가 메인 사이트를 가리키거나 404가 남.
- 항목을 한 파일에 몰아넣어 두 사람이 같은 날 편집하면 충돌하는 구조.
- 글 하나 추가하려고 Astro 컴포넌트나 설정을 건드려야 하는 구조.
- DESIGN.md 밖의 색·서체·둥근 모서리가 들어감.

## 3. 제약

- **스택**: Astro + 마크다운/JSON (사용자 결정). `reference/mpbel/`의 설정·스키마·배포 워크플로·빌드 결과 테스트를 가져와 고쳐 쓴다. 로컬 Node 26, CI Node 24.
- **배포**: GitHub Pages, 조직 `ympbel`, 저장소 `10th`(사용자 결정), `base: '/10th'`. 메인 사이트의 최상위 경로(`en`, `introduction`, `lecture`, `member`, `notice`, `publication`, `research`, `images`, `_astro`)와 겹치지 않는다.
- **디자인**: `DESIGN.md`(MPBEL 디자인 시스템)를 따른다(사용자: "디자인은 DESIGN.md 참고"). 새 시각 세계를 만들지 않는다. 블루 스펙트럼 네 색의 순서, Cobalt 하나로 상호작용 표시, Signal Mint는 진한 블루 위 1–2px 선, Lato + Nanum Gothic 400/700, 모서리 0px, 1200px 고정 그리드와 1024px 이하 유동 레이아웃, 서브 페이지 240px 사이드 메뉴 + 900px 본문.
- **공개 범위** (사용자 결정, 2026-11-02):
  - 공개하지 않음: 전화번호, 이메일, 생년월일·나이, MBTI, 학번, 과학기술인등록번호, 과제 실무담당자 이름, "Jin's 과제 담당" 열, 5공 유무·수료여부 같은 행정 열.
  - 공개함: 논문 IF와 합계, 과제의 연구비 금액·참여율, 졸업생의 현 직장·직급, ORCID(값이 있는 사람만, 링크 아이콘으로).
- **자료의 언어**: 한국어 UI 기본. 논문·발표 제목과 학회 이름은 원문 그대로.
- **읽기 전용**: `../Website_20261028`의 파일은 복사만 한다. `data/`의 원본은 수정하지 않는다.

| 개인 페이지 | `/people/<slug>/` (slug는 영문 이름 기반, 예 `yongdo-yun`; 충돌 시 합류 연도 접미사) |

상단 메뉴는 6개 묶음이다. 메인 사이트처럼 대메뉴는 영문 대문자, 하위 항목은 현재 언어로 쓴다.

| 대메뉴 | 하위 |
|---|---|
| PEOPLE | 학생 현황, 졸업 현황 |
| PUBLICATION | 논문, 특허, 발표 |
| AWARD | 수상 |
| PROJECT | 과제 |
| ACTIVITY | 세미나, 워크샵 |
| ARCHIVE | 사진, Comments |

연도 페이지는 메뉴에 없다. 홈 연표, 연도 페이지 상단의 연도 탭 줄, 경로 표시(홈 › 2026), 각 게시판의 연도 소제목 옆 링크로 간다.

### 5.2 콘텐츠 모델

Astro content collections. **항목 하나가 파일 하나**다. 컬렉션은 언어별로 나누지 않는다(논문·수상·과제는 두 언어에서 같은 항목이다). 한글만 있는 값에 영문이 필요하면 같은 파일에 `*_en` 필드를 둔다. 소개문처럼 언어별로 완전히 다른 글만 `pages/ko/`, `pages/en/`으로 나눈다.

```
src/content/
  pages/ko/home.md, pages/en/home.md   슬로건·소개문 (frontmatter + 본문)
  members/            구성원 한 명이 파일 하나 (교수 포함)
  papers/             논문 217편
  patents/            특허 7건
  presentations/      학회 발표 379건
  awards/             수상 41건
  challenges/         챌린지 참가 5건
  projects/           과제 15건
  seminars/           세미나 431건
  workshops/          _template.md 만
  photos/             _template.md 만 (+ public/images/photos/)
  comments/           _template.md 만
  schemas.ts          모든 스키마는 .strict()
```

`_`로 시작하는 파일은 템플릿이며 컬렉션에서 제외한다(MPBEL과 같음). 날짜는 문자열 `YYYY-MM-DD`(월만 알면 `YYYY-MM`), 연도는 정수다.

주요 필드(정확한 스키마는 빌더가 확정한다. 아래는 있어야 하는 것과 넣으면 안 되는 것):

- **members**: `role` ∈ {professor, student, alumni, former}, `name`(한글), `name_en`, `aliases`(저자 표기 변형 목록, 5.6), `orcid?`, `program?`(석사/박사/통합(석사)/통합(박사)), `department?`, `department_en?`, `major?`, `joined?`(연구실 첫 출근 또는 학위 시작일), `left?`, `degree?: { start, date, type, type_en }`, `affiliation?`, `affiliation_en?`, `position?`, `position_en?`, `order?`. 한 사람이 학위를 받으면 `role`을 `alumni`로 바꾸는 것으로 끝나야 한다. 교수는 `name`, `name_en`, `order`, `link?`(지도교수는 메인 사이트 교수 페이지)만 쓴다. **넣지 않는 것**: 전화, 이메일, 생년월일, 나이, MBTI, 학번, 등록번호, 행정 열.
- **papers**: `year`, `title`, `first_author`(시트 문자열 그대로), `co_first[]`, `corresponding[]`, `journal`, `impact_factor?`, `acknowledgement?`(사사 번호), `projects[]`(과제 slug 목록, 5.7의 과제 대응표로 연결; 비어 있을 수 있음), `members[]`(5.6에서 확정한 구성원 slug), `link?`. 2016년 이전 여부는 `year`로 판단하며 별도 필드를 두지 않는다. "Pf. Kim 교신 여부", IF-교신, IF-공동교신은 내부 집계용이라 가져오지 않는다.
- **patents**: MPBEL의 `publicationSchema`와 같은 필드(`year`, `title`, `authors`, `venue`, `link`).
- **presentations**: `year`, `title`, `authors`(전체저자 문자열), `first_author`, `corresponding[]`, `conference`(표기 통일 후), `conference_raw?`(통일 전 값이 다를 때만), `type`(Oral/Poster/ePoster/…; 표기 통일), `session?`, `acknowledgement?`, `members[]`.
- **awards**: `year`, `recipient`(시트 문자열), `member?`(slug), `conference`, `category`, `category_en?`, `title?`.
- **challenges**: `year`, `host`, `title`, `objective`, `dataset_release?`, `submission?`, `link?`.
- **projects**: `title`, `title_en?`, `nickname`, `agency`, `program`, `institution`, `role`(연구책임자/참여연구원), `start`, `end`, `months?`, `participation_rate?`, `budget_year_krw_thousand?`, `budget_total_krw_thousand?`, `acknowledgement_en?`, `acknowledgement_ko?`. **넣지 않는 것**: 실무담당자, 3책5공여부, 연구내용(비어 있거나 내부 메모).
- **seminars**: `title`, `date`, `presenter?`, `event_date?`, `source_url`.
- **workshops** (템플릿): `title`, `title_en?`, `date`, `place?`, `members[]?`, 본문.
- **photos** (템플릿): `image`(`/images/photos/<yyyy>/<file>`), `year`, `kind` ∈ {lab-meeting, conference, retreat, graduation, equipment, other}, `people[]`(slug), `caption?`, `date?`.
- **comments** (템플릿): `name`, `date`, 본문.

### 5.4 연도 페이지

서브 페이지 틀(240px 사이드 영역 + 900px 본문)을 쓰되, 사이드 영역에는 메뉴 대신 **연도 탭 줄**(2016 … 2026, 메인 사이트 연도 탭 형식, 현재 연도 Cobalt)이 세로로 들어간다. 본문 제목은 "2026", 경로 표시는 "홈 › 2026". 1024px 이하에서는 탭 줄이 본문 위 가로 줄이 된다.

본문 순서: 요약 한 줄(합류 n명 · 학위 n명 · 논문 n편 · 발표 n건 · 수상 n건 · 과제 n건) → 합류한 사람(이름 칩, 개인 페이지 링크) → 학위 취득(이름, 학위 종류, 현 소속) → 논문(제목, 저자, 학술지, IF) → 학회 발표(학회별로 묶어 제목·1저자·형태; 60건이 넘는 해가 있으므로 학회별 소제목으로 나눈다) → 수상 → 진행 중이던 과제(과제명, 부처, 기간) → 세미나 n건(세미나 게시판의 해당 연도로 링크) → 사진(있을 때만). 비어 있는 구역은 "기록 없음"으로 표시하되 구역 자체는 둔다(2016·2017년은 대부분 비어 있다).

- **수상** `/awards/`: 연도별 표(수상자, 학회, 구분, 발표명). 수상자는 개인 페이지 링크. 맨 아래 **"챌린지 참가 (2021)" 구역**에 5건을 표(주최, 제목, 목적 한 줄, 링크)로(사용자 결정).
- **과제** `/projects/`: 시작일 내림차순 목록. 항목마다 과제명(영문이 있으면 영문 페이지에서 영문), 부처·사업명, 수행기관, 역할, 기간(개월), 참여율, 당해년도·총 연구비(천원 단위를 "억/만원"이 아니라 "640,000천원"으로 그대로), 사사 문구(접힘). `projects`에 이 과제가 든 논문이 있으면 "관련 논문 n편"으로 펼침 목록. 연결은 5.7의 과제 대응표를 거친 것만이다.
- **세미나** `/activity/seminars/`: 연도 탭, 연도별 표(날짜, 제목, 발표자). 제목은 메인 사이트의 해당 글로 가는 외부 링크(새 탭). 본문·사진은 없다. 안내문 한 줄: "세미나 본문은 MPBEL 사이트 세미나 게시판에 있습니다."
- **워크샵** `/activity/workshops/`: 항목이 없으면 빈 상태 안내("아직 기록이 없습니다. 추가하는 법은 README 참고")와 항목 형식 설명. 항목이 생기면 날짜 내림차순 목록(제목, 날짜, 장소, 참여 구성원 링크, 본문).
- **사진** `/archive/photos/`: 비어 있을 때 빈 상태 안내. 항목이 생기면 상단에 연도 탭과 종류 탭(랩미팅·학회·MT·졸업식·장비·기타), 4열 격자(1024px 이하 2열, 600px 이하 1열), 사진 아래 캡션·연도·인물 칩(개인 페이지 링크). 탭은 정적 페이지로 만든다(`/archive/photos/<yyyy>/`, `/archive/photos/k/<kind>/`).
- **comments** `/archive/comments/`: 비어 있을 때 빈 상태 안내. 항목이 생기면 날짜 내림차순 글 목록(이름, 날짜, 본문). 글을 받는 방식은 미정이며, 페이지 하단에 "남기는 법"을 쓸 자리만 둔다.

### 5.6 사람과 항목의 연결

- 구성원 파일의 `aliases`는 그 사람이 저자란에 적힌 영문 표기 목록이다(예: 최병수 → `Byong Su Choi`, `Byoung Su Choi`, `Byongsu Choi`). 비교는 소문자화 후 공백·마침표·하이픈 제거로 한다.
- **연결은 변환 때 한 번 하고 결과를 항목 파일에 적는다**(`members: [byong-su-choi]`). 빌드 때 이름을 다시 추측하지 않는다. 그래야 결과가 결정적이고, 틀린 연결을 파일에서 직접 고칠 수 있다.
- 변환 스크립트는 1저자·공동 1저자·교신저자(논문)와 전체 저자(발표)를 구성원 영문 이름·`aliases`와 대조하고, 수상자(한글)는 구성원 `name`과 대조한다. 정확히 맞지 않지만 가까운 표기(성·이름 순서 바뀜, 띄어쓰기 차이, 편집 거리 2 이하)는 **자동 연결하지 않고** `report.md`에 후보로 적는다. 사용자가 `aliases`에 추가하면 다시 돌려 연결한다(`--force`로 `members` 필드만 갱신).
- 개인 페이지는 `members`에 자기 slug가 있는 항목을 모은다. 논문은 1저자·공동 1저자·교신저자인 것만 모인다(시트에 전체 저자가 없다). 이 점을 개인 페이지에 한 줄로 적는다.
- 교수는 개인 페이지를 만들지 않는다(1차). 교수의 논문은 메인 사이트 출판물 목록이 맡는다.

### 5.7 데이터 변환 스크립트

- 위치 `scripts/import/`. Python 3 표준 라이브러리만(`html.parser`, `re`, `json`, `pathlib`). 입력은 `data/*.html`과 `../Website_20261028/src/content/{patents,seminars}/ko/`. 출력은 `src/content/**/**.md`와 `scripts/import/report.md`.
- **열 허용 목록 방식**: 시트마다 가져올 열을 코드에 명시한다. 목록에 없는 열은 읽지도 않는다. 개인정보 열이 실수로 새는 것을 막는 가장 단순한 방법이다.
- 현황 시트는 빈 행으로 구역(현 학생 / 거쳐 간 구성원 / 그룹 / 교수)을 나눈다. 번호 열이 숫자인 행만 구성원이다. 거쳐 간 구성원 중 Alumni 시트에 있는 사람은 한 파일로 합치고 `role: alumni`, 나머지는 `former`. 박예인처럼 현 학생이면서 Alumni인 사람은 `student`로 두고 `degree`만 채운다.
- 날짜는 `M/D/YYYY`, `MM/DD/YYYY`, `YYYY.MM`, `YYYY-MM-DD`를 모두 받아 `YYYY-MM-DD` 또는 `YYYY-MM`으로 쓴다. 연도가 없는 값(`3/1`)은 비워 두고 `report.md`에 적는다.
- 학회 이름은 표기 통일표(`conferences.json`: `KSMP (Fall)` → `KSMP Fall` 등)를 거친다. 표에 없는 새 표기는 그대로 두고 보고한다.
- **논문과 과제의 연결은 과제 대응표(`projects.json`)를 거친다.** 논문 시트의 "과제 이름" 열(값 있는 논문 49편, 값 18종)은 닉네임이 아니라 대개 과제의 정식 이름(연구과제명)이고, 일부는 줄임말("중견", "스위스"), 쉼표·슬래시로 여러 개를 적은 값, 숫자, 과제 목록에 없는 과제명이다. 정식 이름과 정확히 같은 값(32편)은 자동 연결한다. 쉼표·슬래시는 나눠서 각각 대조한다. 줄임말은 대응표에 적힌 것만 연결하고, 과제 두 건 이상에 맞는 줄임말이나 목록에 없는 과제명은 **연결하지 않고 `report.md`에 적는다.** 사용자가 대응표를 채우면 `--force --only members,projects`로 연결 필드만 다시 쓴다. 틀린 연결은 "이 논문이 이 국가과제의 성과"라는 잘못된 주장이 되므로 추측하지 않는다.
- 빈 행, 합계 행(논문 시트 맨 아래), 안내문 행(과제 시트)은 건너뛰고 몇 행을 건너뛰었는지 보고한다.
- 끝나면 컬렉션별 건수를 출력한다. 기대값(구성원 61+교수 8, 논문 217, 발표 379, 수상 41, 챌린지 5, 과제 15, 특허 7, 세미나 431)은 스크립트 안의 표 하나에 두고, 다르면 종료 코드 1.
- **이미 있는 파일은 덮어쓰지 않는다.** 한 번 변환한 뒤에는 사용자가 파일을 직접 고치기 때문이다. `--force`를 주면 덮어쓴다.
- `data/`는 `.gitignore`에 넣는다. 개인정보가 들어 있는 원본이므로 공개 저장소에 올라가면 안 된다. README에 "원본 시트 내보내기는 저장소 밖에 보관"이라고 적는다.

### 5.8 한·영

- 라우팅은 MPBEL과 같다(`i18n: { defaultLocale: 'ko', locales: ['ko','en'], routing: { prefixDefaultLocale: false } }`). 영문은 `/en/` 아래 같은 페이지 구조이고, KR/EN 토글은 **같은 페이지의 다른 언어판**으로 간다(메인 사이트는 `/en/` 홈으로만 갔다).
- UI 문자열은 `src/i18n/ko.ts`, `en.ts`. 메뉴 하위 항목, 게시판 제목, 표 머리글, 빈 상태 안내, 푸터, 연표 라벨, "기록 없음" 모두 두 언어로 쓴다.
- 데이터 필드는 `field_en`이 있으면 영문 페이지에서 그것을, 없으면 한글 값을 그대로 쓴다. 이름은 영문 페이지에서 `name_en`을 앞에 둔다. 논문·발표 제목과 학회명은 두 언어에서 같다.
- 영문 페이지의 `<html lang>`은 `en`, 한글 값이 그대로 나오는 요소에는 `lang="ko"`를 붙인다.

## 6. 작성자가 정한 것 (사용자가 뒤집을 수 있음)

1. **홈에서 메인 사이트의 연구 타일 네 장과 "최근 글" 패널을 뺀다.** 연표와 연도 패널이 그 자리를 맡는다. 사용자가 "C의 연표를 B 아래"라고만 했으므로 B의 나머지 부분은 작성자 판단으로 정리했다.
2. **비주얼 띠 사진은 메인 사이트의 `visual.jpg`를 쓴다.** 같은 연구실의 의료영상이고 디자인 시스템이 그 사진을 전제한다. 새 사진이 오면 바꾼다.
3. **연표 칸은 연도 페이지 링크이고, 홈에서는 JS로 패널만 바꾼다.** JS 없이도 동작하고, 연도 페이지는 공유 가능한 주소가 된다.
4. **컬렉션을 언어별로 나누지 않고 `*_en` 필드를 둔다.** 논문 217편을 두 번 두는 것은 운영 부담이고, 한글만 있는 값을 영문 페이지에서 그대로 보여 주는 것이 번역을 지어내는 것보다 낫다.
5. **사람 연결은 변환 때 확정해 항목 파일에 적는다.** 빌드 때 추측하지 않는다. 가까운 표기는 보고만 하고 자동 연결하지 않는다.
6. **교수는 개인 페이지가 없고, 학생 현황 맨 위 구역에만 나온다.** 사용자가 "학생 현황 맨 위에 교수진 구역"을 골랐다. 지도교수만 메인 사이트 교수 페이지로 링크한다.
7. **합류일이 비어 있으면 Alumni 시트의 학위 시작일을 쓴다.** 조진동·김나리·천재희·박인경·이주영이 해당한다. 그 밖에 날짜가 없는 사람은 연표의 합류 칸에 세지 않는다.
8. **홈 숫자의 "구성원"은 학생·연구원 61명이고 교수는 빼며, "논문"은 2016년 이후 162편이다.** 2016년 이전 55편은 논문 게시판 아래 구역에만 있다. 바로가기 칸의 "논문 217"은 게시판 전체 건수라 다르다. 두 숫자가 다르다는 설명을 논문 게시판 상단 안내문에 쓴다.
9. **세미나는 메인 사이트 글로 링크만 한다.** 본문과 사진을 복사하면 두 곳을 관리해야 한다.
10. **챌린지 참가 5건은 수상 게시판 아래 구역**(사용자 결정)이고, 과제 게시판의 "관련 논문"은 논문 시트의 "과제 이름" 열을 과제 대응표로 풀어 연결한다. 정식 이름이 정확히 맞는 것만 자동으로, 줄임말은 대응표에 적힌 것만, 애매한 것은 연결하지 않는다(5.7). `projects`는 배열이다.
11. **연표 막대의 척도는 항목별 상대값**이다. 발표 379건과 수상 41건을 한 척도에 놓으면 수상 막대가 보이지 않는다. 범례에 적는다.
12. **변환 스크립트는 Python**이다. 한 번 쓰는 도구이고 MPBEL 크롤러도 Python이었다.
13. **`data/`는 gitignore**. 공개 저장소에 개인정보 원본을 올리지 않는다. 빌드 결과 검사에 개인정보 패턴 검사를 넣는다.
14. **발표 게시판은 연도 안에서 학회별로 묶는다.** 한 해 60건이 넘는 목록을 한 줄로 늘어놓으면 읽히지 않는다.
15. **연구비는 시트 단위(천원)를 그대로 표시한다.** 환산하면 반올림 판단이 들어간다.
16. **이 설계 문서는 저장소에 들어간다**(`docs/superpowers/specs/`). 저장소 초기화(로컬 `git init`)는 구현 계획 단계에서 하고, 원격 저장소와 첫 push는 5.10의 사용자 확인 뒤에 한다.
17. **논문과 과제의 연결은 대응표로만 하고 애매한 것은 비워 둔다**(5.7). 빌더 검토에서 "과제 이름" 열이 닉네임이 아니라는 점이 드러나 바꾼 결정이다. 기존에 정리된 대응표가 있으면 사용자가 `projects.json`에 넣는다.
18. **학회 발표의 전체 저자는 머리글 없는 C열과 "전체저자" 열을 합쳐 읽는다**(4장). 두 열 중 비어 있지 않은 쪽을 쓰고, 둘 다 있으면 같은지 확인해 다르면 보고한다.

## 8. 미정과 2차 (이 문서의 범위 밖, 연결 고리만)

- **comments를 받는 방식**: Google Form → 운영자 게시, giscus 등. 정해지면 `/archive/comments/` 하단 "남기는 법"과 README만 바뀐다.
- **사진·워크샵 내용**: 사용자가 제공하면 `photos/`, `workshops/` 파일과 `public/images/photos/`에 넣는다. 형식은 이미 있다.
- **영문 데이터 필드**(`*_en`) 채우기. 비어 있어도 사이트는 돈다.
- **과제 대응표 채우기**: 변환 보고서에 남은 줄임말("중견", "스위스" 등)과 목록에 없는 과제명을 사용자가 `scripts/import/projects.json`에 적으면 연결이 늘어난다.
- **슬로건·소개문 확정**: 사용자가 `pages/ko/home.md`, `pages/en/home.md`를 고친다.
- **도메인 전환**: 메인 사이트가 `mpbel.yonsei.ac.kr`로 가면 `astro.config.mjs`의 `site`를 바꾸고 다시 배포한다. 저장소 이름과 `base`는 그대로다.
- **데이터 추가 변환**: 시트가 크게 바뀌어 다시 변환하고 싶으면 `--force`로 돌리되, 그 사이 직접 고친 파일이 덮어써진다는 점을 README에 적는다.
